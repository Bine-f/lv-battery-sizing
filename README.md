# LV battery sizing

Data-driven sizing and placement of batteries that fix **undervoltages in low-voltage (LV) distribution feeders**.

The tool combines one year of smart meter measurements (voltages and powers, 10 min resolution) with a
[pandapower](https://www.pandapower.org/) model of the LV network. For every feeder with recurring
undervoltages it finds the best smart meter location for a battery and calculates the required
**power (kW)**, **capacity (kWh)** and the expected **number of cycles**.

It was developed as part of my master's thesis. The repository ships with a small **synthetic** network
and dataset, so everything runs out of the box.

## Quickstart

Python 3.10+ is required (tested with Python 3.14, pandas 2.3, pandapower 3.5).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

python src/main.py
```

Output on the demo data:


## Method

1. **Screening** – transformers with at least 4 undervoltage events (any phase below 207 V, i.e. 230 V − 10 %,
   lasting at least 20 min) are selected as candidates.
2. **Preprocessing** – implausible samples are removed (a phase below 170 V or a spread between phases above 30 V),
   isolated single-sample undervoltages are ignored and meters with unrealistically asymmetric phases are dropped.
3. **Network model** – the transformer area is extracted from the network, every load is assigned to its feeder
   and meters are classified as single- or three-phase from the data.
4. **Battery location** – for every feeder with undervoltages on at least 4 timestamps, the battery is placed at
   the meter with the largest cumulative undervoltage.
5. **Calibration and sensitivities** – for a few critical timestamps the model is calibrated to the measurements
   (line impedance scaling factor and transformer secondary voltage), then the voltage sensitivity of every meter
   to a 1 kW injection at the battery location is calculated (V/kW).
6. **Battery operation** – for every 10 min interval the required battery power is the largest
   *voltage deficit / sensitivity* over all meters. When voltages allow it, the battery recharges. The capacity is the
   deepest state-of-charge deficit, the power is the maximum discharging power and the cycles are the discharged
   energy divided by the capacity.

## Results

| Column | Description |
| --- | --- |
| `Trafo`, `Feeder` | transformer and feeder name |
| `N_of_UV` | number of undervoltage samples in the feeder |
| `N_of_smms`, `N_of_smms_with_UV` | number of smart meters, and meters with undervoltages |
| `N_of_dates_with_UV` | number of timestamps with undervoltage |
| `battery_smm` | smart meter at which the battery is placed |
| `battery_capacity` | required capacity in kWh |
| `battery_power` | required power in kW |
| `battery_cycles` | number of full cycles in the analysed period |

## Using your own data

**Network** – a pandapower network saved with `pandapower.to_json`, containing:

- `trafo.name` – contains the transformer name used in the data folder,
- `bus.aclass_id` – `"TR"` for the LV busbar of each transformer (`config.TRAFO_BUS_CLASS`),
- `line.name` – the first line of every feeder contains `"FEEDER"` (`config.FEEDER_LINE_TAG`); its name is used as the feeder name,
- `load.smm` – smart meter id of every load.

**Measurements** – one folder per transformer, files can be plain `.csv` or gzipped `.csv.gz`:

```
data/<trafo_name>/voltage.csv   date_time, smm, u_1, u_2, u_3, u_123   (V, phase voltages and their average)
data/<trafo_name>/power.csv     date_time, smm, p, q                   (kW, kvar)
```

Timestamps should be on a 10 min grid. Single-phase meters leave `u_2` and `u_3` empty. Paths can also be
set with the `LVBAT_NETWORK_PATH` and `LVBAT_DATA_DIR` environment variables.

## Demo data

`data/demo` is generated by [scripts/generate_demo_data.py](scripts/generate_demo_data.py): two transformer
areas with radial cable feeders (one of them long and weak), random household profiles with evening peaks
and occasional EV charging / heat pump loads, and voltages obtained with a power flow for every interval.
It does not represent any real network.

```bash
python scripts/generate_demo_data.py --days 42 --seed 7
```

